# OCR A Level Computer Science H446 NEA Repository Scaffold

This repository is a **student-authored workspace** for planning, documenting, evidencing, and reviewing an OCR A Level Computer Science H446 NEA project. It is structured to support high-mark workflow from proposal and analysis through design, development/testing, and final evaluation.

Write every section in your **own words**. Use this scaffold for structure and prompts, not model answers. Keep references throughout the project (not as a rushed add-on at the end), and record where ideas, code patterns, libraries, websites, AI support, and external help came from.

## Recommended working order

1. `00-admin` (proposal, plan, authenticity, references)
2. `01-problem` (problem definition, stakeholders, computational suitability)
3. `02-analysis` (**backbone**: requirements, measurable success criteria, constraints, traceability)
4. `03-design` (justify decisions linked to requirements)
5. `04-development` (iteration-by-iteration build evidence)
6. `05-testing` (iterative, whole-system, and usability test evidence)
7. `06-evaluation` (evaluate against success criteria and requirements)
8. `07-final` (final checks and submission readiness)

## Requirement IDs and cross-referencing

Use requirement IDs from the start (for example `R1`, `R2`, `R3`):

- Requirements in `02-analysis/requirements-specification.md`
- Success criteria linked to requirement IDs in `02-analysis/success-criteria.md`
- Design sections link back to requirement IDs
- Development iterations and tests link back to requirement IDs
- Evaluation links back to requirement IDs and success criteria

This cross-reference chain should be clear:

**Requirement -> Success criterion -> Design -> Development/Test evidence -> Evaluation**

Use `02-analysis/traceability-matrix.md` to keep this up to date.
