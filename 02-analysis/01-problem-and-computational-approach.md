# Problem and Computational Approach

## 1) What this part is for

You need to prove that:

- the problem is real and specific
- your project has clear boundaries
- a computational solution is suitable for this exact problem

## 2) Writing a clear problem statement

Use this structure:

- **Current problem:** what goes wrong now?
- **Who is affected:** which users/stakeholders?
- **Impact:** what is the consequence?
- **Boundary:** what your solution will and will not cover

### Strong example

> The PE department currently tracks equipment loans on paper forms. Forms are often misplaced, and staff cannot quickly check what is overdue. This causes lost equipment and wasted lesson time. The project will create a desktop loan-tracking system for PE staff in one school. It will not include online parent access.

### Weak example

> I want to make a system for school equipment because it will be useful.

Why weak: too vague, no clear users, no measurable problem, no boundary.

## 3) Scope control (too broad / too small)

- **Too broad:** “Full school management system”
- **Too small:** “One simple calculator screen”
- **Better:** one clear process with meaningful logic, data, and user interaction

Check yourself:

- Can you explain the exact user workflow in 4–8 steps?
- Can you finish this within your NEA timeframe?
- Does it need genuine programming logic (not just static pages)?

## 4) Why this problem suits a computational solution

Avoid generic claims like “computers are faster”.

Explain specific computational benefits in your context:

- storing and retrieving records
- validation rules
- search/filter/sort
- automatic rule checking
- generating summaries/reports

### Strong vs weak wording

**Weak:**

> A computer is better than paper.

**Stronger:**

> The system must validate dates, stop duplicate entries, and search historical records by user and date. These are rule-based tasks that software can perform consistently and quickly.

## 5) End this section with decisions

Finish with 3–5 bullet decisions you will carry into requirements.

Example:

- The project will support staff users only.
- Overdue tracking is a core feature.
- Parent-facing online access is out of scope.
